## Confirmed Findings

### Clang OpenMP Runtime Is Not Loader-Visible

All 90 compiled test executables fail before entering `main` with:

```text
error while loading shared libraries: libomp.so: cannot open shared object file
```

The three CMake-only tests pass because they do not load a GenDiL executable.
All 18 Clang range programs fail identically with exit status 127. This is a
runtime search-path defect, not evidence of a Clang code-generation or GenDiL
correctness failure.

The build script now reads FindOpenMP's absolute runtime library entries from
`CMakeCache.txt` and reconfigures with those directories in
`CMAKE_BUILD_RPATH`. `K3_OPENMP_RUNTIME_DIR` can override discovery. Runners
record the RPATH and OpenMP library cache entries so the correction can be
reviewed from returned logs.

### GCC Range Coverage

Sixteen of 18 GCC smoke benchmarks complete with finite coordinate output.
`range-benchmark-mass-6d` and `range-benchmark-advection-6d` terminate with
exit status 139 and no flushed output. These two host variants instantiate
orders through six, unlike the 6D speed-of-light benchmark, and create large
fixed-size tensor temporaries on OpenMP thread stacks. Stack exhaustion is the
leading hypothesis but is not yet proven; the next run must vary process and
OpenMP stack limits before any kernel implementation changes are made.

The K3 runners now default the process and OpenMP worker stacks to 64 MiB and
record both settings. If the two programs pass with this setting, rerun them at
smaller limits to characterize the minimum requirement. If they still fail,
collect a debugger backtrace rather than increasing the limit again.

No GCC CTest output was included in this result batch. The sole CTest log is
the Clang run and was stored under `unknown-compiler` because CMake represented
`CMAKE_CXX_COMPILER` as `STRING`, while the result script expected `FILEPATH`.
The parser now accepts any CMake cache type.

## Required Rerun

Pull the fixes and execute the complete two-compiler X100 rerun:

```sh
git pull --ff-only
scripts/machines/spacemit-k3/rerun-x100-baseline.sh
```

This rebuilds Clang with the corrected OpenMP RPATH, runs CTest for both
compilers, and reruns all range smoke benchmarks with explicit stack budgets.
It continues through individual failures and returns nonzero at the end if any
step failed.

The range rerun applies the documented 64 MiB stack budget automatically. To
retain the shell's process stack limit, set `K3_STACK_SIZE_KB=0`; set
`OMP_STACKSIZE` explicitly to reproduce a prior OpenMP worker limit.

Do not treat the current Clang result as a compiler failure. Do not begin RVV
performance comparisons until the loader issue and the two GCC 6D crashes are
resolved.

## Rollback

Removing the second configure step in `scripts/machines/spacemit-k3/build.sh`
restores the prior loader behavior. The change affects only build-tree RPATHs;
it does not modify installed headers, installed RPATHs, or GenDiL execution.
Removing `rerun-x100-baseline.sh` removes only the orchestration shortcut; the
underlying build and runner scripts remain independently usable.
