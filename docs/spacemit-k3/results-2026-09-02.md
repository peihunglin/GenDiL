# K3 Heterogeneous Probe Review: 2026-09-02

## Inputs

- Probe code: `7223bb6355f3a554b70fa6259c8ade88ef1cf408`.
- Result commit: `53785d1f050f1bc56b5310dfb5d1c2d76579233c`.
- GCC 15.2 and Clang 24 were tested independently.
- Linux reports RVV enabled by default and exposes writable
  `/proc/set_ai_thread`.

## Single-Process Result

Both compiler builds terminate with `SIGILL` before
`probe_output_begin` receives any program output. The scalar launcher had set
RVV `OFF` for the probe's next `exec`. Therefore some code in executable
loading, runtime initialization, or OpenMP startup executes a vector
instruction before GenDiL can place individual workers.

This is the intended failure mode of the safety gate. Allowing RVV during
startup would hide the violation and permit 256-bit X100 vector state to be
created before selected workers move to 1024-bit A100 cores. The one-process
16-thread design is rejected for the installed runtimes. The vector-state
checks must not be disabled or moved later in startup.

## Superseded Fallback Decision

The initial fallback proposal used two MPI ranks:

- Rank 0 executes through `taskset -c 0-7` and creates eight X100 OpenMP
  workers.
- Rank 1 executes through `aix` and reaches its loader and `MPI_Init_thread`
  only after A100 placement, then creates eight A100 workers.
- The runner disables MPI's own binding with an implementation-specific option;
  each scalar coordinator verifies CPU class and affinity before and after
  `MPI_Init_thread` before any RVV canary executes.
- Both ranks execute scalable FP64 RVV canaries and verify stable VLEN over 64
  OpenMP barriers.
- An MPI all-reduction validates communication and `MPI_THREAD_FUNNELED`.

That MPI proposal was not retained as the active path because the K3 GEMM
reference demonstrates a direct OpenMP worker-placement mechanism. This section
is historical and is not a current installation requirement.

## Historical Commands

The commands that originally attempted to build and run the MPI probe are no
longer valid after the OpenMP rollback. Use the current commands in the main
K3 README, which run `run-heterogeneous-openmp-probe.sh` directly.

## Rollback

The MPI probe is opt-in, not installed, and does not alter GenDiL headers. It
can be removed independently while retaining the failed single-process logs and
design decision.
